المشتبه

لعبة ألغاز تحقيق عربية على شبكة ٥×٥. هذي الوثيقة تحدد القواعد ونموذج البيانات والمحرّك وآلية العمل — قبل كتابة أي سطر كود.

القرار المطلوب

ابدأوا بتطبيق الويب — لكن لا تلغوا الكتاب، أجّلوه

سؤالك كان: نكنسل الكتاب ونكتفي بتطبيق ويب؟ الجواب إن الاثنين مو خيارين متعارضين. آلية الباركود اللي بنيتوا عليها الفكرة تحتاج موقعًا أصلًا — الباركود لازم يفتح صفحة. يعني تطبيق الويب ليس بديلًا عن الكتاب، هو الخطوة الأولى فيه.

ابنوا المحرّك والموقع أولًا، ولّدوا فيه عشرات القضايا، جرّبوها على ناس حقيقيين، وبعد ما تعرفون أي الألغاز نجحت — اطبعوا أفضلها في كتاب. وقتها يصير الكتاب حصيلة مؤكدة، مو مقامرة.

  • 01الخطأ المطبوع دائم. لغز فيه حلّان في تطبيق ويب يتصلح في دقيقة؛ في كتاب مطبوع يبقى للأبد ويكسر ثقة القارئ في الكتاب كله.
  • 02الويب يعطيكم بيانات. أي لغز أوقف الناس، كم واحد أكمل، أي مستوى صعب زيادة. هذي المعلومات ما تجيكم من كتاب مطبوع أبدًا.
  • 03بدون تكلفة طباعة مقدمًا. تختبرون الفكرة كاملة قبل أي التزام مالي أو لوجستي.
  • 04الكتاب يبقى هدفًا. نسخة مطبوعة من قضايا مجرّبة لها قيمة يصعب على موقع منافس يقلّدها.

الخطر الوحيد وانتبهوا له: كتطبيق ويب أنتم تنافسون Murdoku مباشرة، وهو سابقكم بـ٣٦ قضية و٢٣ لغة وواجهة عربية جاهزة. لا تتميزوا بالآلية — تميزوا بـالمحتوى: بيئة سعودية، أسماء وأماكن مألوفة، قصة متسلسلة تربط القضايا، ولهجة تحكي زي الناس.

01

قواعد اللعبة

الشبكة ليست جدولًا للاستبعاد — هي خريطة مسرح الجريمة نفسه، مقسّمة لغرف، وفيها أثاث وأشياء. اللاعب يضع الشخصيات على الخريطة.

القواعد الخمس

القاعدةالتفصيل
واحد لكل صف وعمودكل صف يحتوي شخصية واحدة فقط، وكل عمود كذلك — تمامًا كالسودوكو. وضع شخصية يستبعد صفها وعمودها آليًا.
الغرفالشبكة مقسّمة لمناطق مسماة. الغرفة تحدد نطاق أدلة الجوار — «بجانب» لا تعبر جدارًا.
«بجانب»مباشرة يمين أو يسار أو فوق أو تحت، وفي نفس الغرفة. القُطر لا يُحتسب.
الضحيةإحدى الشخصيات ضحية. دليلها ثابت: «كان وحده مع القاتل» — أي أن غرفتها تضم شخصين بالضبط.
القاتللا يُسأل عنه مباشرة. هو الشخص الوحيد الذي انتهى في غرفة الضحية. يظهر تلقائيًا عند اكتمال الخريطة.

لماذا هذا القيد مهم لكم تحديدًا: في المثال الذي أرسله شريكك (٥ أشخاص، ٥ أماكن، ٥ أدلة) وجدنا ٤٠ حلًا صحيحًا لا حلًا واحدًا. مع قيد السودوكو، خمسة أدلة تكفي لحل واحد فريد. القيد هو ما يجعل اللغز قابلًا للنشر.

02

كل دليل لازم يكون قابلًا للفحص آليًا — أي أن الكود يقدر يحكم عليه بصح أو خطأ لأي وضعية. أي دليل لا يندرج تحت نوع من هذي الأنواع، لا يدخل اللعبة.

04

المحرّك

قطعتان فقط، وهما قلب المشروع كله. لو ضبطتوهما، الباقي واجهات.

أ — المدقّق: كم حلًا لهذا اللغز؟

لأن كل شخصية تأخذ صفًا فريدًا وعمودًا فريدًا، فإن أي وضعية = تطابق بين الشخصيات والصفوف، وتطابق آخر بينها وبين الأعمدة. عدد الاحتمالات الكلي n! × n! — وهو رقم صغير جدًا يسمح بالفحص الشامل بلا خوارزميات معقدة:

حجم الشبكةعدد الوضعياتالحكم
5 × 514,400فحص شامل فوري — أجزاء من الثانية
6 × 6518,400فحص شامل مريح
7 × 725,401,600يحتاج تقليمًا مبكرًا للأدلة
 
// المدقّق — الناتج الوحيد المقبول للنشر هو 1
function countSolutions(puzzle) {
  const chars = puzzle.characters.map(c => c.id);
  let found = 0, first = null;

  // rowPerm: أي شخصية في أي صف · colPerm: أي شخصية في أي عمود
  for (const rowPerm of permutations(chars)) {
    for (const colPerm of permutations(chars)) {
      const placement = {};
      for (const c of chars)
        placement[c] = [rowPerm.indexOf(c), colPerm.indexOf(c)];

      if (hitsBlockedCell(placement, puzzle)) continue;
      if (!puzzle.clues.every(cl => check(cl, placement, puzzle))) continue;

      found++;
      if (!first) first = placement;
      if (found > 1) return { count: found, first };  // حلان = مرفوض
    }
  }
  return { count: found, first };
}

ب — المولّد: من حل إلى لغز

لا تكتبوا الأدلة يدويًا ثم تتمنوا أن الحل فريد. اعكسوا الاتجاه: ابدأوا بكل الأدلة الصادقة، ثم احذفوا منها ما دام الحل باقيًا فريدًا. هذي طريقة مضمونة رياضيًا وتنتج أدلة لا زائد فيها ولا ناقص.

// المولّد — كل دليل ناتج ضروري بالضرورة
function generate(layout) {
  const solution = randomValidPlacement(layout);   // 1. اختر الحل سرًا
  let clues = allTrueClues(solution, layout);      // 2. ولّد كل دليل صادق (مئات)
                                                   //    الحل فريد بالضرورة الآن
  shuffle(clues);
  for (const clue of [...clues]) {                 // 3. جرّب حذف كل دليل
    const trial = clues.filter(c => c !== clue);
    if (countSolutions({ ...layout, clues: trial }).count === 1)
      clues = trial;                               //    بقي فريدًا ⟸ احذفه فعلًا
  }
  return { ...layout, solution, clues };           // 4. أقل مجموعة أدلة ممكنة
}

05

آلية العمل

الرحلة من فكرة قضية إلى قضية منشورة. الترتيب مقصود — كل خطوة تعتمد على اللي قبلها.

  1. ارسم التخطيط

    خريطة ٥×٥: الغرف وحدودها، والأشياء داخلها، والخلايا المحظورة. هذي مهمة تصميم بصري خالصة.

  2. اكتب الشخصيات والقصة

    خمسة أشخاص بأسماء وملامح سعودية، وواحد منهم الضحية. سطر أو سطران يمهدان للقضية.

  3. شغّل المولّد

    يختار حلًا سريًا ويستخرج أقل مجموعة أدلة تؤدي إليه.

  4. شغّل المدقّق

    لا مرور إلا إذا كان الناتج count === 1 بالضبط. أي رقم آخر يعيد اللغز للخطوة السابقة.

  5. صُغ الأدلة بالعربية

    حوّل الأدلة الآلية إلى جمل طبيعية. المعنى لا يتغير — الصياغة فقط. هنا تدخل اللهجة والنبرة.

  6. اختبرها على إنسان

    شخص واحد على الأقل يحلها كاملة بلا مساعدة. لو وصل لحل مختلف أو علق — ارجع للمولّد.

  7. انشرها

    أضف الملف لمجلد القضايا، وحدد مستواها، واربطها بالقصة العامة إن وُجدت.

08

معايير قبول أي لغز

لا يُنشر لغز ولا يُطبع قبل أن تتحقق هذي الشروط كلها. هذي القائمة هي خط الدفاع الأخير قبل أن يصل الخطأ للقارئ.

  • المدقّق أعطى count === 1 بالضبط — لا صفر ولا اثنين.
  • كل دليل ضروري: حذف أي واحد منه يجعل الحل غير فريد.
  • كل دليل يخص فئة موجودة فعلًا في الشبكة — لا وقت ولا أدوات ولا أي بُعد غير مرسوم.
  • غرفة الضحية تضم شخصين بالضبط، فيتحدد القاتل بلا لبس.
  • الصياغة العربية تطابق الدليل الآلي تمامًا — لا زيادة معنى ولا نقصان.
  • إنسان واحد على الأقل حلّها كاملة بلا مساعدة ووصل لنفس القاتل.
  • مستوى الصعوبة مُقاس بالحلّال، لا مُقدَّر بالحدس.
